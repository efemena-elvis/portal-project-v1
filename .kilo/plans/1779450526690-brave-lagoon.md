### 3. `src/modules/fees/modals/edit-fee-modal.vue`  — CREATE + UPDATE plan + CRITICAL FIX
Reuses the modal UI from `add-fee-modal.vue` but pre-fills all fields with the selected fee data using a new `feeData` prop instead of relying solely on `getSingleFee`.

**IMPORTANT — Import fix:** The initial implementation incorrectly imported `useFeeStore` from `@packages/hooks`. `useFeeStore` is a local Pinia store and must be imported from `@/modules/fees/store`. The same applies to any future `add-fee-modal.vue` edits. The error:
```
SyntaxError: The requested module '/packages/hooks/index.ts' does not provide an export named 'useFeeStore' (at edit-fee-modal.vue:120:21)
```

**Root cause of missing prefill:** previously the modal received only `feeId` and relied on a `getSingleFee(feeId)` API call in `onMounted` to populate form fields. If the API response has different field casing or structure (e.g. `country: "Nigeria"` vs `country: "nigeria"`), the defaults in `normalizeIncomingFee` masked the real value, leaving fields blank or incorrect.

**Fix:** accept a `feeData` prop (raw fee row object) and initialize `feePayload` from `feeData` directly. Keep `getSingleFee` on mount as a non-blocking refresh — if the feeData object is stale, the live API call will overwrite values that are wrong — but the initial mount is now always pre-filled from `feeData`.

**Props:**
- `feeId: string` — the fee record id for the update API call
- `feeData: Record<string, any> | null` — the raw fee row object from `selectedFee.raw` with fields: `method`, `country`, `type`, `amount`, `cap_amount`, `name`

**On mount:** initializes `feePayload` from `feeData` directly (no API wait needed for initial prefill). Still calls `getSingleFee(feeId)` as a non-blocking refresh — if the response is valid it updates `feePayload`, but the form was already pre-filled in the first paint.

**Normalize helper:** `normalizeIncomingFee` — lowercases `country`, `type`, `method` values so they match the `<SelectFieldInput>` option values (`"nigeria"` not `"Nigeria"`, `"payin"` not `"Payin"`, etc.)

**CRITICAL — imports in script section of edit-fee-modal.vue:**
```ts

import { useEvents } from "@packages/hooks";
import { useFeeStore } from "@/modules/fees/store";


**Form fields:** Method, Country, Type, Amount, Cap Amount — all pre-filled from `feeData` at mount
**Merchant display:** readonly `<p>` block showing `feeData.name`
**Submit title:** "Update config"
**Emits:** `closeTriggered`, `feeUpdated`

### 4. `src/modules/fees/store/actions.ts`  — ENHANCE
Add two new actions below existing `getFees`:

```ts
// Fetch a single fee
export const getSingleFee = async (id: string) => {
  return await $api.fetch(`fees/${id}`)
}

// Create a fee config
export const createFee = async (payload: any) => {
  return await $api.push('fees', payload)   // POST
}

// Update a fee config
export const updateFee = async (id: string, payload: any) => {
  return await $api.push(`fees/${id}`, payload)  // PUT/PATCH
}
```
